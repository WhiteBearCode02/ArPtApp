# YOLO 학습 외 로드맵 진행 및 검증

## 이번 구현 범위

- `JointAngleMeasurement` API: 내각·굴곡각 변환, 이미지 2D/정규화 좌표 구분, 촬영 시점, 가시성, 누락/퇴화/비유한 값 품질 상태.
- 실시간 카운트: 영상 종횡비를 반영한 2D 각도, 가장 잘 보이는 좌우 관절 선택, 연속 3프레임 및 최소 600ms 정책. 기존 90°/160° 등 공학적 초기 임계값은 유지.
- 가림 발생 시 미완료 반복과 회차 버퍼 폐기. 완료 횟수는 보존. 한 세션은 하나의 종목으로 유지.
- 정면 무릎 정렬/측면 몸통 기울기 코칭을 촬영 방향별로 제한. 주황은 확인할 관절이며 부상 위험 판정이 아님.
- 사용자 개인 기준: 카메라에서 한 동작을 기록해 15~300개 유효 각도 프레임 저장. 최소 20° 움직임 범위는 기록 품질 조건이며 운동 정상 범위가 아님. 종목·촬영 방향·계정별 비교, 길게 눌러 삭제. 개인 기준은 올바른 자세 인증이 아님.
- 기록 화면에서 최근 7일/30일 세션 수, 반복 수, 운동 시간, 참여 일수, 반복 수 가중 평균 점수, 날짜별 반복 수 조회. 현재 기기의 해당 로그인 계정 기록만 사용.
- 카메라 추론 제출을 약 15 FPS로 제한하고 비교 버퍼를 300프레임으로 제한. 처리 FPS/응답 지연/Android 10 이상 발열 단계는 로컬 화면에서 확인.

## 로컬 재현 명령

2026-10-02 최종 검증: `:app:testDebugUnitTest :app:assembleDebug` 성공, Android 단위 테스트 24개 전부 통과(실패/오류 0개). 가로·세로 레이아웃의 리소스 링크와 ViewBinding/Kotlin 컴파일도 이 빌드에 포함됩니다. 연결된 Android 기기가 없어 실기기 조작·성능·발열 검증은 수행하지 않았습니다.

변경 파일 비밀키 패턴 검사에서 노출을 발견하지 않았고 `local.properties`와 생성 APK는 Git 제외 대상임을 확인했습니다. 새 기능은 로컬 계산·저장만 추가하며 새 외부 API/유료 의존성을 추가하지 않습니다. 기존 Supabase 프로젝트의 요금 설정을 변경하지 않았습니다.

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug --offline -PverificationBuildDir=roadmap-verification
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ai_module/requirements-test.txt
.\.venv\Scripts\python.exe -m unittest discover -s ai_module/tests -v
```

별도 빌드 폴더는 Android Studio가 `R.jar`를 점유할 때 검증 경로로 사용합니다. 기본 APK 경로는 유지됩니다. 검증용 APK는 `build/roadmap-verification/outputs/apk/debug/app-debug.apk`입니다.

Python 검증도 2026-10-02 완료했습니다. Python 3.11.9 / NumPy 2.4.6의 프로젝트 전용 `.venv` 환경에서 단위·통합 테스트 10개 모두 통과했습니다. `pip check`는 의존성 충돌이 없었으며 `compileall` 문법 검사도 통과했습니다.

합성 샘플 12개를 임시 폴더에 저장하고 pose NPZ/메타데이터 검증 → manifest 생성 → 실제 split CLI 실행을 확인했습니다. 사람별 train/validation/test 격리, 동일 seed 재현성, 잘못된 배열 크기·운동 오류 라벨 거부도 검증했습니다. 임시 샘플은 테스트 종료 후 삭제됩니다.

저장소의 `ai_module/dataset` 검증은 오류 0개, 경고 1개였습니다. 경고는 실제 sample metadata가 없다는 의미이며 실제 데이터 품질·추론 정확도를 확인한 결과는 아닙니다. 이번 검증에는 실제 영상 추출이나 모델 학습을 포함하지 않았습니다. `.venv`와 Python bytecode는 Git에서 제외합니다.

## 자동 테스트 준비

`.github/workflow-templates/quality-checks.yml.example`은 비활성 CI 템플릿입니다. 현재 push만으로 실행되지 않아 이번 변경이 GitHub 실행 비용을 발생시키지 않습니다. 비공개 저장소에서도 실행하도록 수정하거나 자동 트리거를 켜기 전에는 사용자의 비용 정책 확인·동의를 받아야 합니다. 운영 API 키 없이 컴파일·단위 테스트하도록 구성했습니다.

## 실기기 확인

1. 전면/후면 카메라에서 스켈레톤이 실제 관절에 맞는지 확인합니다.
2. 정면/측면을 직접 선택하고 해당 방향에서 지원하지 않는 오류 코칭이 표시되지 않는지 확인합니다.
3. 관절을 가렸다 다시 나타났을 때 미완료 동작이 횟수로 추가되지 않는지 확인합니다.
4. 천천히 10회 반복하고 수동 횟수와 비교합니다. 반동·빠른 부분 동작·오래 쉬는 입력도 확인합니다.
5. 내 기준 기록 → 저장 → 운동 → 회차별 리포트 → 길게 눌러 삭제를 확인합니다.
6. 계정을 바꿨을 때 개인 기준과 운동 통계가 섞이지 않는지 확인합니다.
7. 최근 7일/30일 통계, 빈 기록, 잘못된 날짜 입력을 확인합니다.
8. 10분 연속 운동에서 FPS·지연·발열 단계를 1분마다 수동 기록합니다. 기기 모델/OS/방향/조명을 함께 기록합니다. 화면의 FPS는 카메라 원본 FPS가 아닌 처리 결과 FPS입니다.

## 외부 검증이 필요한 항목

전문가 annotation 기준의 확정, 실제 데이터로 촬영 방향별 오차/임계값 검증, 기기별 발열·배터리 측정은 코드 테스트로 대체하지 않습니다. 새 코칭과 calibration은 초기 기능이며 이 검증이 끝나기 전 정확도나 성능 향상 비율을 표시하지 않습니다. 학습·데이터 수집은 이번 작업에서 수행하지 않았습니다.
