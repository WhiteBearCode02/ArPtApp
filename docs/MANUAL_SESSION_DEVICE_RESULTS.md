# 7종 수동 선택 — 실기기 결과 기록지

현재 기록 상태: **7종 모두 `USER_NOT_TESTED`**. 이 문서는 사용자가 직접 수행한 결과를 받기 위한 빈 양식이며, 자동 테스트 통과를 실기기 통과로 간주하지 않는다.

## 설치 전 확인

- 실기기 candidate: `build/manual-selection-verification/outputs/apk/debug/app-debug.apk`
- 최종 시연본: `build/deliverables/AIRPTCoach-7Exercises-ManualSelection-demo-debug.apk`. 별도 lint와 로컬 조건의 PASS 후 candidate와 같은 bytes/SHA256으로 복사했다. 상세 근거는 [`MANUAL_SESSION_DEMO.md`](MANUAL_SESSION_DEMO.md)를 참고한다. 이것은 아래 실기기 결과가 PASS라는 뜻이 아니다.
- 사용자가 직접 설치한다. 기존 앱 삭제, 데이터 지우기, History 초기화, 로그아웃, 강제 종료를 테스트 전제 조건으로 요구하지 않는다.
- 운동·저장 중에는 업데이트하지 않는다. 서명 충돌이나 설치 거부가 나오면 오류 문구를 기록하고 멈춘다. 해결을 위해 기존 앱을 임의로 삭제하지 않는다.
- 사진·동영상·모델·Golden 자료를 공유하거나 업로드할 필요가 없다. 아래 텍스트 결과만 전달하며 이메일, 비밀번호, 토큰, 기기 일련번호는 적지 않는다.

기기 모델/OS(일련번호 제외): ___ / 테스트 날짜: ___ / 설치한 APK 파일명: ___

## 무엇이 같아야 하는가

`selected exercise → sessionExerciseType → 측정·카운터·분석·TTS·Report·History`가 같은 종목을 유지해야 한다. 제목은 **선택한 한국어 운동명 + `운동 중`**, 횟수 단위/종목 표시도 선택한 운동명이어야 한다.

`detectedExerciseType`은 Landmark 자동 분류의 **진단 관측값**이다. 예를 들어 `selected=SIDE_BEND`, `detected=SQUAT`, `session=SIDE_BEND`는 수동 고정 정책상 허용된다. 감지 결과가 다르다는 이유만으로 routing 실패로 기록하지 않는다. 반대로 session/title/counter가 SQUAT로 바뀌면 실패다.

- 선택한 종목은 실제 수행한 운동의 정답 증거가 아니다. 이 테스트만으로 자동 분류 정확도나 모델 성능을 평가하지 않는다.
- UI/진단 패널에서 값을 실제로 읽을 수 없으면 **`NOT_OBSERVABLE`**로 적는다. 선택값을 복사해 session 관측값으로 꾸미거나 로그를 수집했다고 주장하지 않는다.
- DEBUG 진단을 볼 수 있다면 시작 직후와 종료 직전의 session/detected를 각각 기록한다. 개인정보가 포함된 전체 로그·저장소 덤프는 요구하지 않는다.
- 선택을 취소하면 운동/TTS/카운트가 시작되지 않아야 한다. 종료 후 다음 세션에서는 다른 운동을 다시 선택할 수 있어야 한다.

## 수행 순서와 촬영 방향

목록은 `ExerciseType.supported`의 7종과 `displayName`을 기준으로 한다. `LUNGE`, `UNKNOWN`, `IDLE`은 선택 대상이 아니다. 방향은 전면/후면 **렌즈**가 아니라 몸을 촬영하는 **정면/측면**이다.

| 운동 | enum | 촬영 방향 | 이번 확인 동작 |
|---|---|---|---|
| 스쿼트 | `SQUAT` | 정면 또는 측면 | 5회 |
| 숄더 프레스 | `SHOULDER_PRESS` | 정면 또는 측면 | 5회 |
| 바이셉 컬 | `BICEP_CURL` | 정면 권장 | **한 팔 5회**. 어느 팔인지 기록한다. 기존 정책상 양팔 동시 완료는 좌우 각각 count될 수 있다. |
| 푸시업 | `PUSH_UP` | **측면 권장** | 5회. 정면 기존 지원은 유지되지만 모든 측면 분석 지표를 얻는 것은 아니다. |
| 벤트오버 덤벨 로우 | `BENT_OVER_ROW` | **측면 권장** | 5회. 정면 기존 지원은 유지되지만 모든 측면 분석 지표를 얻는 것은 아니다. |
| 오버헤드 트라이셉스 익스텐션 | `TRICEPS_EXTENSION` | 정면 또는 측면 | 5회 |
| 덤벨 사이드 벤드 | `SIDE_BEND` | **정면 필수** | 중립에서 시작해 **오른쪽 5회 + 왼쪽 5회**. 양쪽 결과를 나눠 적는다. **스쿼트 무릎 피드백이 나오면 실패**다. |

기존 코드 근거: `domain/classifier/ExerciseType.kt`, `domain/session/ExerciseCameraViewPolicy.kt`, `domain/analyzer/PoseAngleExtractor.kt`, `domain/analyzer/ExerciseMeasurementStrategy.kt`. 새 각도·안전 기준이나 classifier threshold를 정의하지 않는다. 무리한 반복이나 통증이 있는 자세로 테스트하지 않는다.

1. 관절이 충분히 보이도록 구도와 촬영 방향을 정한다.
2. `운동 시작 → 종목 선택` 후 제목·단위와 초기 count `0`을 확인한다.
3. 선택/session/자동 감지를 아래 표에 관측한 그대로 적는다.
4. 편안한 범위에서 해당 동작을 수행하고 실제 수행 횟수와 앱 count를 따로 적는다. 기존 체류·복귀 조건을 충족할 시간을 준다.
5. 완료 TTS와 피드백의 종목이 맞는지 확인한다. 안 들렸다면 기기 음량/음소거 여부도 별도로 적고 성공으로 처리하지 않는다.
6. 종료·결과 저장 후 Report를 확인하고, History에서 **방금 저장한 항목**을 다시 열어 운동명·횟수·상세 분석을 확인한다. 기존 기록은 수정·삭제하지 않는다.
7. 다른 종목을 선택하는 다음 세션에서 count `0`, 새 제목, 새 종목 라우팅으로 초기화되는지 확인한다.

## C. 실패 위치를 구분하는 메모

수동 선택으로 종목이 고정되므로 count 실패를 곧바로 자동 분류나 학습 실패로 결론 내리지 않는다. 먼저 아래 증거를 구분한다. 실제 frame/measurement를 읽지 못했다면 원인은 **미확정**으로 남긴다.

| 구분 | 관측할 증상 | 우선 확인할 근거 |
|---|---|---|
| `ROUTING` | 선택과 session/title/단위/분석 종목이 다름 | 시작·종료 selected/session, 변화 시점. detected만 다른 경우는 이것만으로 실패 아님 |
| `MEASUREMENT` | 관절 누락/가림/촬영 방향 안내, 측정 불가가 이어짐 | 촬영 방향, 관절 가시성, 실제 표시 문구. 없는 각도를 0으로 간주하지 않음 |
| `COUNTER` | session은 맞는데 count가 부족/과다함 | 실제 횟수와 앱 count, 중립·복귀·체류, 한팔/양팔, 관측 가능한 measurement. classifier threshold부터 조정하지 않음 |
| `TTS` | 시작·완료 음성 누락 또는 다른 종목 음성 | 실제 들은 짧은 문구, 발생 시점, 기기 음량 상태 |

## 경계와 다음 단계

- Landmark 자동 분류는 diagnostic only, YOLO는 Shadow다. EXP04는 **`NOT_VERIFIED` 유지**다. 이 결과지나 7종 수동 시연 통과만으로 모델을 VERIFIED/Production으로 승격하지 않는다.
- 새 API·유료 SDK·서버 업로드·환경 변경을 이 기록 절차에서 추가하지 않는다. 기존 계정 동기화의 사용량/요금제까지 무료라고 보장하는 것은 아니다.
- 이 문서 작성은 실기기 실행·로그 수집·기록 저장·보안 전체 감사를 뜻하지 않는다. 사용자가 전달한 결과만 A/B/C에 반영한다.
- 7종 실기기 결과를 분류해 문제를 해결하고 모두 통과한 뒤, 보존된 EXP04 Golden/environment 근거를 바탕으로 기존 검증을 재개한다. 기존 모델·Golden·venv·증거를 삭제하거나 변경하지 않는다.
